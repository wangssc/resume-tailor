# 写法库（按需加载，不必每次读）

## 一、同构挂靠公式

把 JD 职责翻译成素材里**结构相同**的动作。左列是 JD 类型，右列是可复用的改写骨架。

| JD 类型 | 可挂靠的素材与写法 |
|---|---|
| 招商 / 商业地产 / 2B 销售 | 学生会外联、社团赞助 → 「资源摸排 → 拜访 → 需求挖掘 → 方案报价 → 条件谈判 → 签约履约」全链路；**放实践经历首位** |
| O2C / 商务运营 / 订单管理 | 销售或客服兼职 → 「端到端付款闭环」「回款零坏账」「漏斗统计与缺口预判」「个案分级响应」 |
| 风控 / 内控 / 信息化 / 安全 | 信息安全类课程 + 实验 → 「资产识别 → 威胁分析 → 脆弱性评估 → 风险处置」；ITGC / 等保 2.0 / 备份策略与恢复演练写成「概念级」 |
| AI 应用 / AI 产品 | 自学项目 → 多模型横向对比 + 能力边界与幻觉记录 + 工作流编排（提示词—知识库—工具调用—流程节点）+ 人机协同 + 效果度量（准确率 / 采纳率） |
| 售前 / 解决方案 | 客户侧沟通经历 → 「需求挖掘 → 方案转译 → 异议应答 → 回访维护」；校内评审汇报 = 应标汇报同构 |
| 数据分析 / 建模 | 课程项目 → 数据清洗（pandas）→ 特征构建 → 模型训练 → 评估指标（AUC / F1）→ 结论输出 |
| 管培生（多类岗合并） | 选匹配最高或专业不限的方向为主意向，求职意向栏写「意向方向：X」，其余能力做差异化补充 |
| 实习转正岗 | 头部第三行改「可尽早实习、全职到岗」+ 自我评价里表态长期投入 |
| 技术开发岗 | 课程项目 + 竞赛 → 技术栈 + 模块职责 + 遇到的具体问题与解决路径；框架类无实战就写「了解 IoC/AOP、分层架构、ORM 映射」 |

**通用句式**：`<b>标签：</b>业务背景 + 我的动作 + 方法/工具 + 量化结果`
一句之内只放一个主张，别堆三件事。

## 二、概念级弱口径词表（JD 要求但用户不会时用）

了解 Spring Boot / MyBatis（IoC、AOP、分层架构、ORM 映射）｜Linux 常用命令与 Web 部署｜容器与镜像基本概念｜Redis 缓存穿透、消息队列削峰、ES 检索场景｜REST API 请求流程｜数据库索引与事务隔离级别｜ERP / PLM / OA 的定位差异｜等保 2.0 与 ITGC｜模型推理链路（训练 → 导出 → 服务 → 监控）｜BI 工具（FineReport / Tableau）应用场景

用法：写进「课余自学」板块或专业能力里，用「了解 / 概念级 / 自学过」，并提醒用户面试前真跑一遍。

## 三、版面经验（目标底部留白 30-50pt）

- 13-16 个 bullet 通常对应 39-57pt 留白
- 技术类 bullet 偏长，最容易超页：首版就预留 2 条可删的冗余
- 偏空时的补充优先序：拆细已有条目 → 加「客户/协作」维度 → 加课余自学与行业认知细节
- 超页时的精简优先序：合并同类 bullet → 删最弱一条 → 压缩「专业能力」与自我评价
- 判定必须靠 PDF 实测坐标，不能凭感觉；`/Count` 元数据不可靠

## 四、事故教训（都踩过）

1. 简历正文出现「（对标职责X）」类注释 → 曾一次清理 55 处，务必生成后 grep 自检
2. 台账手动插入时把文末锚点标题吃掉 → 永远用 `add_record.py`
3. 用「head 切片 + 数据行」拼接重写台账 → 整表重复，序号出现两轮；批量整理必须先按序号去重
4. 备注写成长篇 JD 拆解 → 表格变论文，用户不会看；≤80 字，只留亮点/缺口/面试点
5. 把没做过的框架项目写进简历 → 面试必崩；写进去就必须先真做一遍
6. 「保上岗」「零基础转行月薪过万」类 JD → 招转培，先查注册资本与主营业务再决定
